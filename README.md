# 席くじアプリ

職業訓練校での席決めを想定して制作した、Spring Boot製のWebアプリケーションです。

参加者が自分の名前を選択して抽選を行うと、空いている席の中からランダムで座席が割り当てられます。  
抽選済みの参加者は再抽選できず、管理者のみ個別リセット・全リセットが可能です。

## 制作背景

職業訓練校で複数人の座席を決める際に、各自のPCから簡単に抽選できる仕組みを作れないかと考え、学習課題として制作しました。

利用環境では専用のサーバーやデータベースを新たに用意することが難しかったため、各PC上でSpring Bootアプリを起動し、共有フォルダ上の参加者データを参照する構成としています。

単に抽選処理を実装するだけでなく、実際に複数PCから利用することを想定して設計しました。

## 主な機能

- 参加者名をプルダウンから選択
- 1〜10番の空席からランダムに座席を抽選
- 抽選済み参加者の再抽選防止
- 現在の座席状況を画面上に表示
- 管理者による参加者ごとの抽選リセット
- 管理者による全参加者の抽選リセット
- Javaオブジェクトのシリアライズによるデータ保存
- 複数PCから共通データを参照

## アプリケーション構成

```text
src/main/java
└─ com.kyoyu.seatlottery
   ├─ controller
   │  └─ HTTPリクエストの受付、画面へのデータ受け渡し
   ├─ service
   │  └─ 抽選処理、座席管理、リセット処理
   ├─ repository
   │  └─ 参加者データの保存・読み込み
   └─ model
      └─ 参加者情報を保持するクラス

src/main/resources
├─ templates
│  └─ Thymeleafを使用したHTML
└─ static
   └─ CSS
```

Spring BootのController / Service / Repositoryといった役割分担を意識して実装しました。

## 抽選処理

```text
1. 1〜10番の座席一覧を作成
2. 使用済みの座席を除外
3. 残った座席からランダムに1席選択
4. 参加者に座席番号を設定
5. 参加者データを保存
```

これにより、同じ座席が重複して割り当てられないようにしています。

## データ保存方式

参加者情報は、`Participant` オブジェクトのリストをJavaのシリアライズ機能を利用してファイルに保存しています。

実運用では、参加者データファイルを共有フォルダに配置し、複数PCから同じファイルを参照することで抽選状況を共有しています。

> 公開リポジトリには、訓練校固有の共有フォルダパスや実際の参加者データは含めていません。

## 工夫した点

### 実際の利用環境を想定した構成

単一PC上だけで完結するアプリではなく、複数PCから利用することを想定しました。

### 再抽選の防止

一度座席が決定した参加者は、通常操作では再度抽選できないようにしています。

### 座席の視覚化

抽選結果を番号だけで表示するのではなく、実際のテーブル配置をイメージした座席表として表示しています。

## 開発中に発生した問題と学んだこと

### ファイルパスの問題

開発PCでは相対パスで動作していましたが、JAR化して実行した際に、実行場所によって参加者データを参照できなくなる問題が発生しました。

この経験から、実行環境に依存しないファイルパス設計の重要性を学びました。

### ファイル読み込み失敗時のNullPointerException

参加者データの読み込みに失敗した際、`null`が返された状態で後続処理を行ったため、`NullPointerException`が発生しました。

この経験から、例外処理や戻り値の設計について改善の余地があると感じました。

## 今後改善したい点

- ファイルパスを設定ファイルから変更できるようにする
- ファイル読み込み失敗時の例外処理を改善する
- 複数ユーザーが同時に抽選した場合の競合対策
- Spring FrameworkのDIをより活用する
- データ保存方式をファイルからデータベースへ変更する
- テストコードを追加する

## 実行方法

Java 25がインストールされた環境で以下を実行します。

```bash
java -jar seatlottery-0.0.1-SNAPSHOT.jar
```

起動後、ブラウザで以下にアクセスします。

```text
http://localhost:8080/
```

※実運用版は共有フォルダ上の参加者データを参照する構成です。別環境で実行する場合はデータ保存先の設定変更が必要です。
